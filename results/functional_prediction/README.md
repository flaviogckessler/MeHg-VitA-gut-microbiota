# PICRUSt2 functional predictions

These directories contain the analysis-ready, unstratified PICRUSt2 predictions used for downstream figure generation. Files are separated by sequencing batch and named by their contents.

| File | PICRUSt2 pipeline source | Contents |
|---|---|---|
| `enzyme_commission_abundance.tsv` | `EC_metagenome_out/pred_metagenome_unstrat.tsv.gz` | Enzyme Commission abundance by sample |
| `kegg_ortholog_abundance.tsv` | `KO_metagenome_out/pred_metagenome_unstrat.tsv.gz` | KEGG Ortholog abundance by sample |
| `metacyc_pathway_abundance.tsv` | `pathways_out/path_abun_unstrat.tsv.gz` | MetaCyc pathway abundance by sample |
| `weighted_nsti.tsv` | `KO_metagenome_out/weighted_nsti.tsv.gz` | Per-sample weighted NSTI quality metric |
| `kegg_ortholog_abundance_legacy_ko2.tsv` | legacy export; exact transformation undocumented | Preserved `KO2` checkpoint, not a primary PICRUSt2 pipeline export |

The EC, KO, and MetaCyc files previously curated from `Data_metadata/picrust/` were validated against the newly supplied original PICRUSt2 pipeline directories. All six files match the compressed pipeline outputs line-for-line after the EC and KO first-column header was renamed from `function` to `ID`. The MetaCyc files required no content change. The weighted NSTI files are direct decompressions of the pipeline outputs.

## KEGG-pathway KO z-score heatmap sources

The KO-level heatmap source tables for Figure 7, Figure 8, and Figures S8-S16
are generated by
[`generate_kegg_pathway_ko_z_scores.R`](../../scripts/04_functional_prediction/generate_kegg_pathway_ko_z_scores.R).
The workflow:

1. reads the canonical batch-specific `kegg_ortholog_abundance.tsv` file and
   normalizes its `ko:K#####` identifiers in memory;
2. selects F1-PND21, F1-PND365, or F2-PND365 samples through the canonical
   [`sample_manifest_all_batches.csv`](../../data/metadata/sample_manifest_all_batches.csv),
   including only `include_primary_analysis` samples;
3. loads KO membership for each selected KEGG pathway from the versioned
   [`kegg_reference.RData`](../../data/reference/ggpicrust2/kegg_reference.RData)
   stored inside the repository;
4. calculates the mean abundance of every measured pathway KO in `CN`, `VitA`,
   `MeHg`, and `VitA+MeHg`; and
5. standardizes each KO across those four treatment means with R's sample
   standard deviation.

The 19 clean CSV files are stored in each batch's
`kegg_pathway_ko_z_scores/` subdirectory and follow the pattern
`<cohort>_<pathway_id>_ko_z_scores.csv`. Their columns are `ko_id`, `CN`,
`VitA`, `MeHg`, and `VitA+MeHg`; no artificial row-number column is written.
Rows with four identical treatment means retain `NA` z-scores, matching the
legacy source data and making the undefined standardization explicit.

The two source locations are
[`batch01_iontorrent_dams-f0_f1-pnd21/kegg_pathway_ko_z_scores/`](batch01_iontorrent_dams-f0_f1-pnd21/kegg_pathway_ko_z_scores/)
and
[`batch02_illumina-miseq_f1-f2_pnd365/kegg_pathway_ko_z_scores/`](batch02_illumina-miseq_f1-f2_pnd365/kegg_pathway_ko_z_scores/).
In addition to supplying the heatmap values, these CSV files were used as the
numerical coloring reference when the KEGG pathway panels—often panels A-D of
Figures 7, 8, and S8-S16—were prepared manually at
[`https://www.kegg.jp/pathway/mapxxxxx`](https://www.kegg.jp/pathway/mapxxxxx).
Here, `xxxxx` represents the five-digit pathway code in the individual figure.

The generator has no dependency on the copied legacy CSVs or the retained
`legacy_ko2` matrices. In both batches, the canonical KO matrices were verified
to be exactly identical to the legacy KO2 matrices after normalizing the
canonical `ko:` prefix (same rows, columns, order, and numeric values). Legacy
checkpoint filenames and tables are referenced only by the validator. The
pathway IDs in the generator are explicit figure-source specifications, not
values discovered from or read out of the checkpoint filenames.

The repository-local reference is an unchanged copy from `ggpicrust2` 2.0.0.
The generator validates its MD5 checksum and internal structure before use, so
the workflow does not depend on an installed package or computer-specific R
library path. Reference provenance is documented in
[`data/reference/ggpicrust2/README.md`](../../data/reference/ggpicrust2/README.md).

Run the generator and its complete regression validation from the repository
root:

```r
source("scripts/04_functional_prediction/generate_kegg_pathway_ko_z_scores.R")
generate_kegg_pathway_ko_z_scores()
source("scripts/04_functional_prediction/validate_kegg_pathway_ko_z_scores.R")
validate_kegg_pathway_ko_z_scores()
```

The validator regenerates every table in a temporary directory, compares it
with the committed clean output and the unchanged legacy checkpoint under
[`results/legacy_summary_tables/figure_7_8_s8_s16/`](../legacy_summary_tables/figure_7_8_s8_s16/),
and checks each finite row for mean zero and unit sample standard deviation.

The portable supplementary heatmap renderer and its figure-specific entry
points are documented in
[`supplementary_figures/README.md`](../../supplementary_figures/README.md).
[`validate_figure_s8_s16.R`](../../supplementary_figures/validate_figure_s8_s16.R)
checks the exact finite KO sets used in the ten S8-S16 heatmaps, including the
ten undefined constant-profile rows omitted by the historical `na.omit()`
rendering step.

Figure S16 uses the F2-PND365
`f2_pnd365_ko00311_ko_z_scores.csv` source and matching
`ko00311__F2_1year.csv` legacy checkpoint.

## Figure 6 use

Figure 6 panels A-C read only the two canonical `kegg_ortholog_abundance.tsv` files. The scripts normalize the pipeline's `ko:K#####` identifiers to the `K#####` form expected by `ggpicrust2::ko2kegg_abundance()` in memory; the source files remain unchanged. The EC, MetaCyc, weighted-NSTI, and `_legacy_ko2.tsv` files are not used for Figure 6. See [`figures/README.md`](../../figures/README.md) for the panel-to-source and panel-to-script mapping.

The reconstructed historical downstream environment uses `ggpicrust2` 2.0.0 and `ALDEx2` 1.28.1. This assignment is based on the legacy script's explicit R 4.2 user-library path, surviving package DESCRIPTION metadata, installation dates that predate the retained final Figure 6, and the independently preserved `ggpicrust2` 2.0.0 KEGG reference. R 4.2.x, likely R 4.2.1, is contextual runtime evidence. No historical `sessionInfo()`, dependency lockfile, or GitHub commit SHA survives, so the versions are recorded as an evidence-backed environment reconstruction rather than an exact session snapshot.

Each pathway is evaluated with one four-treatment omnibus ALDEx2 GLM; Figure 6 does not calculate post-hoc pairwise tests. The workflow preserves the adjustment returned by ggpicrust2/ALDEx2 as `package_p_adjust`, then applies the author's additional conservative rule `author_sixfold_omnibus_p = min(1, 6 * raw_omnibus_p)`. The same value is copied to the legacy-compatible `p_adjust` field used by the panel-selection code. The factor of six reflects the six possible treatment pairs but remains a penalty on the omnibus p-value and must not be presented as an adjusted pairwise-test result.

Functional predictions and downstream analyses use PICRUSt2, ggpicrust2, ALDEx2, and KEGG [@picrust2; @ggpicrust2; @aldex2; @kegg].
